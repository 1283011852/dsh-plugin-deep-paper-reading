# 可视化规范（Visualization Spec）

> 本文件与 `SKILL.md` 的 Phase 7 配套。凡「必做」项，缺一项即视为报告未完成；「条件」项由触发条件决定；「可选」项不得为了好看而加。
> 目的很具体：精读报告的读者（journal club、组会）要在 30 秒内看到**论文的骨架**和**证据的缺口**。纯文字的逻辑链不满足这个要求，因此文本流程图不是合格交付。

三维分工，不要混用：

| 载体 | 负责什么 | 不负责什么 |
|---|---|---|
| **状态/关系图**（Mermaid → PNG） | 结构：谁接谁、为什么接、哪一步断了 | 具体数值、完整图注 |
| **矩阵/散点图**（render-diagram.py） | 判断：一致/存疑/矛盾、严重度、影响面 | 论证细节 |
| **表格**（Markdown 表） | 精确数据：n、p、货号、分组、原文句子 | 整体结构直觉 |

**图不替代表。**任何出现在图里的判定，都必须同时能在对应表格或正文中找到逐条依据；反过来，表格里的关键判定必须上到图里，否则读者看不到。

---

## 1. 三条硬规则

1. **图与数据并存（No figure without its table）**
   图是索引，表是证据。删掉表只留图 = 过度概括；删掉图只留表 = 读者看不出结构。

2. **可溯源（No figure without a source line）**
   每张图底部必须有「来源：Fig 2A–C；Results §2.1 第 2–3 段；Table S1」这样的行。图里出现的每个事实都必须能追到图注、表、正文段落或补充材料。`scripts/render-diagram.py` 对缺 `source` 的 spec 直接报错，这是刻意的。

3. **失败要标注（No silent placeholders）**
   渲染器缺失、字体缺 CJK、补充材料没拿到——都要在报告里显式写出「未渲染（原因）」/「缺失（正文引用但未获取）」。**不允许**用 ASCII 方块假装是流程图，也不允许留空白占位符假装已附图。

## 2. 图形清单

编号固定，报告与 Word 导出都用这套编号（`figures/V1-*.png`）。

| 编号 | 图名 | 章节 | 类型 | 级别 | 最低要求 |
|---|---|---|---|---|---|
| **V1** | 全文逻辑链主图 | 二、逻辑链 | flow | **必做** | 至少 5 层（背景→空白→假说→实验→结果→结论）；每条边标过渡类型；断裂点用虚线 |
| **V2** | 主干与分叉 | 二、逻辑链 | flow | **必做** | 只画主干：核心假说 → 关键 2–3 个实验 → 核心结论；侧枝实验折叠为一个节点 |
| **V3** | 正文↔图 映射二分图 | 三、图注对应 | flow（两列） | **必做** | 左列 Results 小节/段落，右列图号；一对一、一对多、无对应都要能看出 |
| **V4** | 图注-正文一致性矩阵 | 三、图注对应 | matrix | **必做** | 行=图（主图逐张，或按图合并小图）；列=图注自洽 / 正文一致 / 统计可查 / 图像可辨 |
| **V5** | 实验总览矩阵 | 四、逐实验拆解 | matrix | **必做** | 行=实验；列=在体证据 / 正交验证 / 剂量或时间梯度 / 对照完备 / 效应量可估 |
| **V6** | 论证强度阶梯 | 七、批判性评读 | matrix 或 timeline | **必做** | 每个核心主张一格：充分 / 部分 / 不足，并注明支持它的图号 |
| **V7** | 局限风险矩阵 | 七、批判性评读 | scatter | **必做** | 每点一条局限；x=对结论影响，y=方法学严重度；致命项必须有 |
| **V8** | 术语/机制关系图 | 八、术语表 | flow | **必做** | 基因→蛋白→通路→表型→干预手段的关系；只画本文用到的 |
| **V9** | 替代假说判别树 | 七、批判性评读 | flow（树） | **条件**：作者未排除 ≥1 个替代解释时必做 | 每个分支给一个能判别的实验 |
| **V10** | 入组/队列流程图 | 五、补充材料 或 四 | flow | **条件**：临床、队列、患者样本研究 | 人数在每个节点闭合（n 的加减要对得上） |
| **V11** | 实验推进时间线 | 四、逐实验拆解 | timeline | **可选** | 论文有明确的分阶段推进（发现→功能→在体→转化）时价值最高 |
| **V12** | 评估雷达 | 六、方法统计 | 不提供渲染器 | **可选** | 只有 5 个轴都能给出评分锚点时才用；否则用 V5+V6 代替 |

**图形预算**：必做 8 张 + 条件图最多 3 张。超过 11 张说明在拿图凑数，砍到读者真会看的那几张。

**小论文例外**：论文主图 ≤ 3 张、实验 ≤ 3 个时，**V2 可并入 V1**（在图 1 的图注里注明「V2 已并入」，并在附录 A 的 V2 行写「并入 V1」）。理由：三步主干在五层链路里已经看得见，再画一张只会稀释 V1。除此之外 V1、V3–V8 不可减免——它们各自回答不同问题，且都不依赖论文篇幅。

**矩阵规模上限**：任何矩阵的行或列单独超过 10 时，必须按图合并、按小节合并，或拆成两张，否则格子密到没人数。这条同时适用于 V4（逐图）与 V5/V6（逐实验/逐主张）。

`V12` 是唯一没有内置渲染器的类型：雷达图在两类坐标轴语义不清时极易制造虚假精度，本技能的默认答案是**不画**。确实要画时用 Mermaid `radar-beta`（注意是 `radar-beta`，不是 `radar`；`axis`/`curve` 语法，且不支持 `accTitle`/`accDescr`，需在图上方加一段说明），并在表 7.4 里逐轴写出评分锚点（1/3/5 各自对应的原文事实）。

## 3. 选型决策表

| 你想让读者看到 | 用哪种图 | 不要用 |
|---|---|---|
| 论文按什么顺序推进、每步为什么需要 | V1 flow | 折线图、饼图 |
| 哪一步是跳跃 | V1 里的 `leap` 虚线边 | 文字加粗 |
| 正文和图的覆盖关系（有没有图没被正文解释） | V3 二分图 | 表格逐行罗列（读者看不出覆盖） |
| 每张图在几个维度上「站得住」 | V4 矩阵 | ✅/⚠️/❌ 混排在表格文字里 |
| 实验之间证据强度的差别 | V5 矩阵 | 堆叠柱状图（会暗示可比的数量） |
| 每条主张的证据够不够 | V6 阶梯 | 一个总分（把异质证据压成一个数） |
| 哪些局限会致命 | V7 散点 | 局限列表（没有优先级） |
| 分子/通路之间怎么连 | V8 关系图 | 术语表文字堆叠 |
| 患者怎么被筛进来的 | V10 流程图 | 一段方法学描述 |

## 4. Mermaid 硬约束

报告里保留 Mermaid 源码（文本真源，可 diff、可复制），PNG 是由它或由 spec 渲染出的成品。

- 每个图必须有 `accTitle`（3–8 词）和 `accDescr`（1–2 句）。这两个字段同时充当 Word 图像替代文本，不是装饰。
- **只用 `classDef` 上色，不用行内 `style`；不用 `%%{init}`**（会在深色模式/导出时崩）。
- 节点 id 用 `snake_case` 英文（`exp_1`、`res_2`），**中文只放 label 里**。id 里塞中文会让部分渲染器报解析错误。
- 单图节点上限 **25 个**。超了就拆：V1 管主干，细节拆到 V2 或实验章节。
- 边标签用过渡类型中文词（排除/扩展/机制/应用/验证/跳跃/矛盾），与表 2.2 完全一致。
- 方向统一 `TD`；二分图用 `LR`。

## 5. 渲染阶梯

按顺序尝试，第一档成功即停。**报告必须记录实际用了哪一档。**

| 档 | 工具 | 命令 | 适用 |
|---|---|---|---|
| A | mermaid-cli | `mmdc -i figures/V1.mmd -o figures/V1-logic-chain.png -b white -w 2000 --scale 2` | 复杂图、需要 Mermaid 原生样式 |
| B | npx 拉取 | `npx -y @mermaid-js/mermaid-cli -i ... -o ...` | 档 A 未安装但有 Node 与网络 |
| C | 内置渲染器（离线） | `python render-diagram.py figures/V1.json --out figures/V1-logic-chain.png --mermaid figures/V1.mmd` | 无网络/无 Chromium；四类图（flow/matrix/scatter/timeline）全部支持 |
| D | 未渲染 | 在报告中保留 Mermaid 代码块，图片位置写「图形未渲染（原因）」 | 以上都不可用 |

档 C 的定位是**兜底而不是首选的降级**：它给你确定的排版与中文字体，但只覆盖四类拓扑。确认环境：

```bash
python render-diagram.py --selftest --tmp /tmp/diagram-check
```

自检会渲染四类样图并检查「缺 source 必须报错」这条规则是否真的生效。若提示 `no CJK font found`，中文字会变成方框——此时改用档 A，或装一个中文字体，不要交付方框图。

## 6. spec 字段（档 C）

```jsonc
{
  "kind": "flow",              // flow | tree | matrix | scatter | timeline
  "lang": "zh",
  "title": "图 V1｜全文逻辑链",
  "subtitle": "分层 + 过渡类型 + 断裂点",
  "source": "Fig 1–5；Results §2.1–2.5",   // 必填，缺失即报错
  "layers": [{"name": "背景", "nodes": ["bg"]}],
  "nodes": {"bg": {"label": "uPAR 高表达", "role": "context", "tag": "已知"}},
  "edges": [{"from": "bg", "to": "gap", "type": "neutral", "label": "承接"}]
}
```

`role` 取值决定配色：`context` / `gap` / `hypothesis` / `experiment` / `result` / `interpretation` / `conclusion` / `implication` / `risk` / `supplementary`。

`type` 取值决定连线颜色与是否虚线：`support` `elimination` `extension` `mechanism` `application` `validation` `neutral` **实线**；`leap` `contradiction` **虚线**。实线=作者有实验支撑的推进，虚线=我们看到但作者没补的缺口——**这条视觉区分是 V1 的核心价值，不要为了好看改掉。**

其余三类 kind 的字段，见 `assets/diagram-specs.md` 的可直接改写示例。

---

## 7. 配色与无障碍

- 角色色板固定在 `render-diagram.py` 的 `ROLE_STYLE`，Mermaid 用同一组 `classDef`（`assets/diagram-specs.md` 已给出对应行）。
- **颜色永远不是唯一编码**：矩阵每格带 `○ / △ / × / –` 字形，过渡类型同时有线型（实/虚）和文字标签。
- 灰度打印必须仍可读：填色一律浅色（L > 85%），描边深色，正文色 `#1F2937`。
- 对比度 ≥ 4.5:1；禁止渐变、阴影、3D、图标装饰。

## 8. 文件与命名

```
paper-reading/<slug>-精读报告.md      # 报告本体，含全部 Mermaid 源码
paper-reading/figures/V1-logic-chain.png
paper-reading/figures/V1-logic-chain.json   # 档 C 的 spec，便于复现
paper-reading/figures/V1-logic-chain.mmd    # 对应的 Mermaid 源码
paper-reading/sources/paper-fulltext.txt
paper-reading/sources/fig1.png
```

规则：ASCII 文件名、`V<编号>-<kebab 名>.<ext>`、同一张图的三种载体（png/json/mmd）共用同一基名。中文名在 Word 与跨平台传输里迟早出事。

## 9. 图注格式

图下三行，缺一不可：

```
图 V1　全文逻辑链：从 uPAR 高表达（已知）到「可干预靶点」（作者结论）
　　　　断裂点：结果 2 → 结论 之间缺少人体样本证据（虚线红）
　　　　来源：Fig 1–5；Results §2.1–2.5；Table S1；渲染：档 C
```

- 第一行：编号 + 一句「这张图让读者看懂什么」，不是图注复述。
- 第二行：这张图暴露的问题（有则写，没有写「未发现结构性缺口」——但通常会有）。
- 第三行：来源 + 渲染档位。缺来源的图不允许进报告。

## 10. 反模式

| 反模式 | 为什么不行 |
|---|---|
| 用 ASCII/文字框当流程图 | 不是图，读者仍要逐行读；导出 Word 后排版会崩 |
| 图里出现正文没有的数字 | 违反证据边界；无法溯源 |
| 用图形替代精确表格 | 丢掉 n、p、货号、原文句子 |
| 相关性画成实线因果箭头 | 视觉上做了作者没做的推断 |
| 把所有小图都塞进一张 V4 | 行列超 10×10 后没人看；按图合并或拆分 |
| 给评估打总分或画雷达图凑满分 | 虚假精度；异质证据不可相加 |
| 图好看但漏掉正文与图的矛盾 | 精读的全部意义就在这类矛盾上 |
| 未渲染却留空占位符 | 交付前必须能指出 PNG 文件路径与其像素尺寸 |

- [ ] 图中每个中文标签在 PNG 里都是真汉字（不是方框）
- [ ] 虚线边（跳跃/矛盾）在 V1 中非空，且与表 2.2 的归类一致

- [ ] 报告正文在每张图前置一句「这张图回答什么」，图后不重复画中内容
