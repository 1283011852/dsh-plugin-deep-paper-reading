# Word 格式转换标准（DOCX Conversion Standard）

> 适用对象：`deep-paper-reading` 产出的《深度阅读报告》从 Markdown 转为 `.docx` 的全过程。
> 版本：v1.0（与插件 v0.2.0 同步）。本文件是**规范性**文本：带「必须」的条目没有例外，带「建议」的可以说明理由后偏离，偏离理由写进交付说明。
> 一句话立场：**Markdown 是内容真源，DOCX 是排版成品。**转换过程中不允许新增或删改任何事实、数字、判定；转换只改变呈现，不改变证据。

---

## 0. 适用与裁决顺序

冲突时按下列顺序裁决，上位优先：

1. 论文原文与用户明确要求（用户说「不要目录」就不加目录）
2. 本标准的**证据类**条款（D5 表格列数、D6 图注三行、D14 缺失呈现）——这些条款保护的是可核查性，不可为美观让步
3. 本标准的**排版类**条款（字号、行距、边距）
4. Markdown 报告中的既有格式（缩进、层级、临时强调）

**不属于本标准范围**：会议的投稿模板（按期刊/会议要求）、PPT 讲稿（走 `scientific-slides`）、期刊要求的双栏 LaTeX。

## 1. 交付物与命名

| 项 | 规定 |
|---|---|
| 报告正文 | `<短标题 slug>-精读报告.docx`，与 `.md` 同名同目录 |
| 图形资产 | `figures/V*-*.png`（ASCII 名，见可视化规范 §8），**必须随 docx 一起交付**，不内嵌源 spec 的路径依赖 |
| 图片目录 | docx 内不引用外部图片链接；python-docx/docx-js 均以 `add_picture` 内嵌，禁止 `INCLUDEPICTURE` 域 |
| 版本后缀 | 修订稿用 `-v2`、`-审阅`。禁止 `最终版_真的最终版` 这类命名 |
| 临时文件 | 转换中间产物放 `build/`，交付前可删 |

**必须**：交付回复中给出 docx 绝对路径 + 文件字节数 + 页数（如可测），并说明「哪些图已渲染、哪些未渲染」。

## 2. 页面与分节

| 项目 | 数值 | 说明 |
|---|---|---|
| 纸张 | A4 21.0 × 29.7 cm | 不用 Letter |
| 页边距 | 上 2.4 / 下 2.4 / 左 2.4 / 右 2.2 cm | 右边距略小以容纳较宽判定表 |
| 正文宽度 | ≈ 16.4 cm | 图最大宽度 15.5 cm，表最大宽度 16.0 cm |

| 分节 | 封面、目录、正文各一节（新页起始） | 便于目录只覆盖正文 |

编号与层级：

- 章号用阿拉伯数字加顿号：`一、`→ 改为 `1`（技术报告惯例）；**全文只用一种**：要么 `1 / 1.1 / 1.1.1`，要么 `一、/（一）/1.`。**必须**与 Markdown 报告的层级同构，便于读者两边对照。
- 图表编号连续：`表 1…表 N`、`图 1…图 N`，V1–V12 编号写在图题括号里保留（`图 1（V1）　全文逻辑链`），方便与 `figures/` 文件名核对。

目录：

- 自动目录域（`TOC \o "1-3" \h \z \u`），单独一页，位于封面之后。
- python-docx / docx-js **无法计算页码**：必须同时在文档设置里写 `w:updateFields val="true"`，并在交付说明里提示「首次打开请右键目录 → 更新域」。这不是可选提示，是必须写明的已知限制。
- 禁止手工敲「…… 12」这种假页码。

## 5. 表格规范

必须执行的硬约束：

1. **列数 ≤ 6**。超过 6 列必须三选一：转置为行、拆成两表、降级为「图 + 附录完整表」。横向超宽的表格在 A4 上必然挤压文字。
2. **表题在表上方**（中文惯例），格式 `表 N　标题`，黑体 10.5 pt，编号加粗，表题下一行居中表格；**图题在图下方**——两者方向相反，这是最常见的错位。
3. **首行跨页重复**：跨页表格必须设 `tblHeader`，否则第二页起没有列名。
4. **禁止单元格纵向合并造成语义歧义**；必须合并时，合并块内文字左对齐到首行。
5. **对齐**：文本列左对齐；数值列右对齐；判定列居中。单位写在列头（`n`、`p`、`浓度 (nM)`），不在每格重复。
6. **单元格内文字 ≤ 120 字**；超过改子表或下沉到附录。判定列只放 `○ / △ / × / –` + 短词（≤ 6 字）。
7. **样式二选一**：数据表用三线表（上下框线 1.5 pt、表头下 0.75 pt，无竖线）；判定表用全网格（`#E2E8F0` 0.5 pt）+ 状态底色（见 D7）。同一文档内不混用两种。
8. 行高最小 0.6 cm；表格不设固定行高上限，但要检查末行未被切开。
9. 表格不跨节；表后必须留一个空段落再接下一个小标题，避免表与标题粘连。

**禁止**：用表格排版正文段落；用表格画流程图（那是 V1 的活）；用空格或全角字符对齐列。

## 6. 图形规范

| 项目 | 规定 |
|---|---|
| 格式 | PNG（截图/位图）优先；矢量可用 EMF/SVG，但**必须同时提供 PNG 回退**（旧版 Word 与 WPS 对 SVG 支持不一） |
| 分辨率 | 300 dpi；`render-diagram.py` 默认 `--scale 2` 即达标 |
| 像素下限 | 宽度 ≥ 1200 px（本渲染器 2 倍缩放下的四类图均满足） |
| 版心宽度 | 15.5 cm 居中；**高度 ≤ 18 cm**（正文高 24.9 cm 的 ~72%，留出图注与页眉页脚）；超高必须拆图，不缩到看不清 |
| 宽高缩放 | 按原始宽高比缩：`宽 = min(15.5 cm, 18 cm × W/H)`。只设宽不设高会得到 ~25 cm 高的图，A4 正文装不下，图与图题必然被拆到两页 |
| 环绕方式 | 嵌入型（inline），不用「四周型」——浮动图在转 PDF/他人编辑时必错位 |
| 图题 | 图下方三行：① `图 N（V编号）　一句「这张图让读者看懂什么」` ② 缺口/结论行 ③ `来源：… ；渲染：档 A/B/C/D` |
| 替代文本 | 必填，取 Mermaid 的 `accDescr` 或 spec 的 `subtitle`；这是无障碍要求，也是图版检索的唯一手段 |
| 未渲染 | 用 1×1 带边框灰色表格占位（`#F1F5F9`），内写「图形未渲染（原因：…）；源码见附录 N」。**禁止**留空段落、禁止用 ASCII 方块图冒充 |
| 图表引用 | 正文必须出现「见图 N」；图的首次出现顺序 = 编号顺序 |

**必须**：插入图片后核对像素尺寸（用 Pillow 或 `office-docx` 的图片检查），并把「图 N：宽 × 高 px」记入交付说明的核验行。没核对过就说「已附图」属于虚假交付。

规则：

- 正文与表格正文颜色只用 `#1F2937` / `#374151`，**禁止**用彩色文字强调（强调用加粗）。

- 禁止渐变、阴影、3D、图标堆砌、Emoji 当唯一语义（`✅` 在部分中文字体下缺失字形，用 `○ △ ×`）。

## 8. 数学、单位与符号

| 对象 | 规范 | 反例 |
|---|---|---|
| 基因/基因名 | 斜体大写：*PLAUR*、*KRAS* | PLAUR（正体） |
| 蛋白 | 正体：uPAR、p53（人蛋白按惯例小写 p 正体） | *uPAR* |
| P 值 | 斜体 *p*，等号两侧空格，三位小数或 `<0.001`：*p* = 0.032 | P=0.032、p<0.001（P 大写） |
| n / 统计量 | 斜体 *n* = 6 | n=6 |
| 单位 | 数值与单位间空格；不用中文单位：5 mg/kg、37 °C、2 h | 5mg/kg、37度 |
| 温度/角度 | 数字与 ° 之间不加空格：37 °C 写作「37 °C」（° 属单位一部分，空格在 °C 前） | 37°C（可接受但不统一） |
| 负号 | `−`（U+2212），非连字符 `-` | −0.42 写成 -0.42 |
| 乘/除以 | `×`、`/`，不用 `*` | 1.2×10⁴ |
| 上下标 | 用 Word 上下标，不用 `^`/`_` | IC₅₀ → IC50（下标） |
| 公式 | 单行公式居中，编号右对齐 `(1)`；变量斜体、单位正体 | — |

## 9. 语言与中英混排

- 报告语言跟随用户（中文用户 → 中文报告）。**必须**保留原文专名：基因、蛋白、载体、试剂、软件、菌株、细胞系、引文标题不改写、不音译。
- 首次出现的缩写给全称：`uPAR（urokinase plasminogen activator receptor，尿激酶型纤溶酶原激活物受体）`，之后用缩写。
- 中文与西文/数字之间留一个半角空格（`在 4 例样本中`、`用 ImageJ 定量`）。
- 括号：中文语境用全角（），内部纯西文时可用半角 ()，同段内一致。
- 标点：中文句号 `。`，不用 `.` 结尾；引用原文时保留英文标点并用引号标明。
- 引用原文必须可核：`“As shown in Fig. 2A, uPAR was …”`（Results §2.1，第 2 段）。**不得**改写后仍加引号。

## 10. 分页与版式细节

- 标题设置「与下段同页」（`keep_with_next`），避免标题孤立在页底。
- 图与其图题、表与其表题**不得跨页分离**：图题段与前图同页，用 `keep_with_next` 绑在图前段或把图与图题放进同一段内。
- 段落「孤行控制」开启（`widow_control`）。
- 章标题另起一页（H1 前分页）；节标题不分页。
- 表格前后各留 6 pt，禁止紧贴正文。
- 不留空白页；末尾不留孤立半页（除附录源码外）。

## 11. 转换流水线（必须按序）

| 步 | 动作 | 产物 | 失败即停 |
|---|---|---|---|
| 1 | **冻结** Markdown 报告：确认所有 `[ ]` 占位符已替换、所有 `【】` 已替换 | `*.md`（只读） | 是 |
| 2 | 收集图源：`figures/*.json` / `*.mmd` → 渲染 PNG（按渲染阶梯选档，记录档位） | `figures/V*.png` | 是（缺图走 D6「未渲染」规则并记录） |
| 3 | 图检：每张 PNG 存在、宽度 ≥ 1200 px、中文非方框、文件名 ASCII | 图检记录 | 是 |
| 4 | 建骨架：先定义全部段落样式与表格样式，再写内容（顺序反了会出现手工覆盖格式） | 空文档 + 样式表 | 是 |
| 5 | 灌内容：按 D4 映射顺序写章节；表格按 D5 校验列数 | 半成品 | 是（列数超 6 必须处理） |
| 6 | 插图：`add_picture` 嵌入 + 图注三行 + alt text | 成品初稿 | 是 |
| 7 | 页码/页眉/目录域 + `updateFields` | 成品 | 否 |
| 8 | 文档属性：title / author / subject / keywords / comments（含原文 DOI） | 成品 | 否 |
| 9 | 验收：跑 D13 清单 + 视觉复核（转 PDF 逐页看字体回退、表格溢出、图片模糊） | 交付 | 是（清单未过不得交付） |

工具选择顺序（先能用先得）：

1. `office-docx` 技能（python-docx + 自带 LibreOffice 校验）——**首选**，可编程设定 `eastAsia` 字体与表格样式
2. `docx` 技能（docx-js）——需要精确控制 `columnWidths`、`PositionalTab` 时
3. Pandoc `--reference-doc`——只在已有企业模板、且接受字体不易精细控制时使用

## 12. Word 中的证据边界（D14）

这条最容易被排版美化悄悄破坏：

- **缺失项必须可见**：拿不到的补充材料、未渲染的图、只读到摘要的论文，一律用「提示框」样式呈现，不得改成灰色小字、不得塞进脚注、不得删除。
- 「证据等级」声明放**封面**和**第一节末尾**两处，不只在文末。
- 图注第二行的「缺口/存疑」不得因排版拥挤而省略——它是这张图存在的理由。
- 判定符号不得被替换成「是/否」等更温和的说法；`×` 就是 `×`。
- 转 PDF 后核对：提示框底色与左边线仍在、缺失文字未被分页切断。

## 13. 验收清单（25 项，逐项打勾）

**结构**
- [ ] 页边距/纸张为 A4 与 D2 数值一致
- [ ] 封面存在且含标题、DOI、报告日期、证据等级声明
- [ ] 目录为自动域，含 `updateFields`，交付说明已提示更新
- [ ] 章号体系全文唯一且与 Markdown 同构
- [ ] 页眉/页脚页码正确，封面不显示页眉、不编码

**样式**
- [ ] 中文字体与西文字体分别设定（抽查 3 处：正文、表格、标题）
- [ ] 无手工覆盖格式（抽查 3 个段落，样式均来自样式表而不是直接格式）
- [ ] H1 另起一页；标题未孤立在页底
- [ ] 代码块使用等宽字体且未自动断行

**表格**

## 14. 已知限制（必须如实告知用户）

1. **目录页码不会自动算**：python-docx/docx-js 只写域代码，页码由 Word 打开时计算。交付时必须说明「右键目录 → 更新域」，否则用户会看到空目录。
2. **字体依赖客户端**：文档只声明字体名；若读者机器无「黑体/宋体」，会回退到本地替代字体，视觉会变。跨平台交付建议改用「思源黑体/思源宋体」并嵌入字体（Word「文件→选项→保存→嵌入字体」），但嵌入式字体会显著增大文件。
3. **SVG 支持不一致**：旧版 Word 与部分 WPS 版本对 SVG 渲染不稳定，因此规定「SVG 必须配 PNG 回退」。
4. **网页版 Word / Google Docs**：`updateFields` 行为不一致，表格固定列宽在 Google Docs 中可能重排，需目视复核。
5. **无渲染器时确实没有图**：这是事实，不是排版问题。此时按 D6 占位并保留 Mermaid 源码，**不要**用文字画图冒充。
